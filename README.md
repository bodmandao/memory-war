# MEMORY WAR

A persistent, adversarially-tested knowledge layer for machine-generated
claims — built on 0G, with a live mainnet deployment.

Autonomous agents produce claims constantly and cheaply. MEMORY WAR gives
those claims a place to be disputed, investigated by independent parties,
mechanically resolved, and permanently recorded — instead of being taken
on faith or silently forgotten. An agent can also pay the protocol
directly to verify a claim: `POST /agent/verify-claim` runs
pay → investigate → attest → resolve end to end and returns a
machine-readable, independently auditable result.

```
CLAIM → PREDICATE INTERPRETATION → EVIDENCE → CHALLENGE / VERIFICATION REQUEST
      → LOCKED EVIDENCE BUNDLE → INDEPENDENT INVESTIGATORS
      → 0G COMPUTE TEE ATTESTATION → REPORTS → MECHANICAL RESOLUTION
      → ON-CHAIN SETTLEMENT → PERMANENT HISTORY
```

The protocol never outputs "Truth." It outputs an evidentiary verdict
about a claim, at a particular point in time, produced by a disclosed,
mechanical procedure that anyone can re-run over the same reports.

**This repository has a real, resolved case on 0G mainnet** — not a
staged fixture. See [Mainnet Deployment](#mainnet-deployment).

## The Problem

A claim generated by one model is, by default, indistinguishable from a
verified fact to every other model or agent that reads it downstream.
There is no adversarial process forcing a contested claim to be disputed,
no independent investigation before it propagates, and no permanent,
queryable record of what was actually resolved versus merely asserted.
Machine-generated knowledge compounds errors silently unless something
forces disagreement into the open and settles it accountably.

## What MEMORY WAR Does

- **Claims are never trusted by default.** A claim is recorded,
  content-addressed, and given a permanent identifier — that's it. It
  carries no truth value until something resolves it.
- **Genuine contradictions get disputed; related claims don't.** A
  predicate-disambiguation gate (`packages/protocol-core/src/predicate.ts`)
  decides whether two claims genuinely contradict each other or merely
  relate, refine, narrow, or extend one another. Only a real
  contradiction is forced into a bonded, adversarial challenge — the
  contract itself rejects trying to force anything else through that
  path (`NotContradiction`).
- **Investigation is independent and evidence-locked.** Evidence is
  committed and locked *before* investigators see it, so it can't be
  altered mid-dispute. Independent investigators evaluate the same
  locked bundle without seeing each other's conclusions, and issue
  signed, attested reports.
- **Resolution is mechanical, not discretionary.** A disclosed procedure
  (`mw-default/v1`) — not a vote, not an admin key — turns reports into a
  verdict. It requires reports from at least two distinct model
  providers before returning anything but `INCONCLUSIVE` (model-monoculture
  mitigation enforced in code). Disagreement is preserved as `CONTESTED`
  with the dissenting report kept in full — never averaged away.
- **Settlement and history are permanent and on-chain.** Investigator
  payment happens atomically with the verdict, in the same transaction.
  Nothing is ever deleted; a claim that gets superseded stays fully
  queryable, marked `SUPERSEDED`, not erased.

## Why This Needs an Adversarial Knowledge Layer

Reputation-only or single-model self-verification schemes have no cost
for being wrong and no independent check before a claim propagates.
MEMORY WAR's answer is economic and structural, not social: disputing a
claim costs a bond, investigation is independent and blind, resolution
is a pure function of the reports actually submitted (auditable and
re-runnable by anyone), and the outcome — including *disagreement* — is
committed on-chain where it can't be quietly edited later.

### Chain

`MemoryWarRegistry.sol` and `InvestigatorRegistry.sol` are deployed to
**0G mainnet** (chain ID `16661`, `https://evmrpc.0g.ai`). The full claim
state machine is enforced entirely on-chain: claim/challenge IDs,
predicate and text hashes, evidence bundle roots, bond escrow, every
state transition, verdict commitments, supersession pointers, and
append-only appeal records. See [Mainnet Deployment](#mainnet-deployment)
for the deployed addresses and a real resolved case.

### Storage

Evidence bundles, claim text, and investigator reasoning are uploaded to
the live 0G Storage network via `@0gfoundation/0g-storage-ts-sdk`
(mainnet indexer `indexer-storage-turbo.0g.ai`) and are content-addressed
by the protocol's own canonical hash (`contentHashOf`) — the same
identifier committed on-chain as `Evidence.id` / `evidenceBundleHash`.
The protocol commits and *verifies* evidence against that hash — it does
not just store arbitrary files and hope they match later. A real upload
was round-tripped byte-for-byte against mainnet and independently
re-verified (see `docs/AUDIT.md`, Addendum 6). If live configuration is
missing or the network is unreachable, the adapter falls back honestly
to a labeled `LOCAL_DEMO` mode — it never upgrades a label past what
actually happened.

### Compute

Investigator execution runs through the 0G Compute broker
(`@0gfoundation/0g-compute-ts-sdk`) with genuine TEE attestation: a
result is only ever labeled `0G_COMPUTE_TEE` with `verified: true` if
`broker.inference.processResponse()` independently confirmed it for that
exact response. This has been demonstrated live, including in the
resolved mainnet case below. **It runs on 0G testnet, not mainnet** —
0G Compute is not documented as being available on mainnet at all, so
the adapter deliberately uses its own dedicated testnet wallet
(`OG_COMPUTE_CHAIN_RPC_URL` / `COMPUTE_PRIVATE_KEY`), entirely separate
from the mainnet deployment wallet, so a mainnet-funded key can never be
reused for compute by accident. Every report that didn't earn TEE
verification is labeled `LOCAL_LLM` or `SIMULATED` instead — nothing is
ever upgraded past what actually ran.

### Payments

There is no separately published "0G Pay" SDK to integrate against —
none exists publicly as of this build. What's built instead is the real
rail 0G Chain already provides: native on-chain token settlement.
`requestVerification(claimId)` lets an agent pay a fee for a
no-adversary, no-dispute verification; `_settleBond` pays investigators
their execution fee out of the pool first, regardless of verdict (100%
for a verification request, 20% on an adversarial challenge, with the
existing win/lose rule applied to the remainder). Settlement happens in
the same on-chain transaction as the verdict — see the resolved mainnet
case below for a real example with real payout amounts.

### DA

`packages/protocol-core/src/daBatch.ts` implements a real, tested,
order-independent Merkle commitment over a batch of events
(`computeBatchCommitment`) and the actual throughput heuristic for when
batching would be worth it (`shouldBatchForDA`) — this is real code, not
a placeholder. It is labeled **`COMMITMENT READY`**, not live, because no
official 0G DA TypeScript client exists to call for real as of this
build, and every evidence artifact in this protocol is already
individually content-addressed and verifiable — there isn't a
data-availability problem to solve today. Full reasoning:
[`docs/DA_DECISION.md`](docs/DA_DECISION.md).

### ERC-7857 / Agentic ID

Deliberately not used. ERC-7857 makes an agent's intelligence a private,
transferable secret — the right primitive for a proprietary trading bot,
wrong for an investigator, whose entire value is that its model
identity, reasoning, and track record stay public and non-transferable.
`InvestigatorRegistry.sol` is built instead, closer to an ERC-8004
Identity Registry: a persistent `investigatorId` that survives key
rotation (`rotateController`) and records explicit version lineage
(`parentId`), with no `transfer()` at all. Full reasoning:
[`docs/ERC7857_DECISION.md`](docs/ERC7857_DECISION.md).

## Architecture

| Layer | Holds | Package |
|---|---|---|
| 0G Chain (`MemoryWarRegistry.sol`) | Claim/challenge IDs, predicate & text hashes, evidence bundle roots, bond escrow, state transitions, verdict commitments, supersession, appeals | `contracts/` |
| 0G Storage | Full claim text, evidence artifacts, investigator reasoning text | `packages/zg-adapters/src/storage.ts` |
| 0G Compute | Investigator execution; TEE-attested reports bound to a committed evidence bundle hash | `packages/zg-adapters/src/compute.ts` |
| Indexer (not authoritative) | Rebuilds the full claim graph by replaying on-chain events; hydrates text via the storage adapter | `apps/indexer/` |
| Client | Claims explorer, claim/challenge/verdict detail, investigator identities, playground, agent API docs | `apps/client/` |
| Demo / agent API | Scenario drivers + the pay-per-verification agent-facing endpoint | `demo/` |

The indexer holds no authoritative state: `apps/indexer/src/eventStore.ts`
is a pure function `(logs) -> state`. Delete `.data/` and restart, and
the exact same state rebuilds by replaying the chain's own event log.
Full architecture writeup, including the honesty contract that governs
every 0G integration label: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Running Locally

No 0G credentials required for the local devnet path:

```bash
npm install

# 1. terminal A — local EVM devnet
npm run chain:node

# 2. terminal B — deploy the contracts, then copy the two printed
#    addresses into .env as MEMORY_WAR_CONTRACT_ADDRESS and
#    INVESTIGATOR_REGISTRY_ADDRESS (cp .env.example .env first)
npm run chain:deploy:local

# 3. run the tests
npm test                # protocol-core + zg-adapters (vitest)
npm run test:contracts  # MemoryWarRegistry + InvestigatorRegistry (hardhat)

# 4. run the demo end-to-end
npm run demo:full        # tamper detection, then scenarios A, B, C
npm run demo:c           # scenario C alone — pay-per-verification + portable investigator identity

# 5. or drive it from the browser
npm run demo:server      # terminal C — demo driver, :4401
npm run indexer:dev      # terminal D — read-only query API, :4400
npm run client:dev       # terminal E — client (Next.js), :4402
```

Open `http://localhost:4402`. All of it reads real indexed on-chain
state and triggers real transactions — nothing in the client is mocked
or pre-recorded.

### Connecting to a live 0G network

Copy `.env.example` to `.env`. To point at 0G **testnet** (Galileo, chain
ID `16602`), set `CHAIN_RPC_URL=https://evmrpc-testnet.0g.ai` and a
funded testnet `CHAIN_PRIVATE_KEY`, then `npm run chain:deploy:testnet`.
To deploy your own copy to **mainnet**, set `CHAIN_RPC_URL=https://evmrpc.0g.ai`
and a funded mainnet key, then `npm run chain:deploy:mainnet` — this
moves real value; only do this with a wallet you control. Either way,
set `OG_STORAGE_INDEXER_RPC` and `OG_STORAGE_MODE=live` /
`OG_COMPUTE_MODE=live` to use live 0G Storage/Compute instead of the
local fallback. Every adapter degrades honestly (`LOCAL_DEMO` /
`LOCAL_LLM` / `SIMULATED`) if live configuration is missing or
unreachable — see `packages/zg-adapters/src/storage.ts` and
`compute.ts`, and `docs/0G_INTEGRATION.md` for exactly what's real,
simulated, or deliberately not integrated, and why.

## Agent Verification API

`POST /agent/verify-claim` (served by `demo/server.ts`, `npm run
demo:server`) runs the full pipeline against a caller-supplied
`{ claim, evidence[], counterClaim? }` and returns a verdict, the
investigator reports and their attestation modes, the exact payment
breakdown, and an `onChainTxHash` that anyone can independently verify
against the indexer. It's a convenience orchestrator using this
service's own funded demo keys, not a hidden source of truth — every
field it returns is re-derivable from chain state. Documented and
runnable directly from the client at `/verify`.

## Current Limitations

- **0G Compute runs on testnet, not mainnet** — by design, since 0G
  Compute is not documented as available on mainnet at all. See
  [0G Integration → Compute](#compute).
- **0G DA is commitment-ready, not live** — the batching math is real
  and tested; there is no live network call because no official 0G DA
  TypeScript client exists yet. See [0G Integration → DA](#da).
- **A public 0G mainnet RPC node has, at least once, permanently
  dropped a successful transaction's logs** (confirmed via independent
  `eth_getLogs`, not a transient lag) — a real infrastructure defect on
  that specific node, not a bug in this codebase. Documented in full in
  `docs/AUDIT.md`; consistent with 0G's own documented recommendation to
  use a third-party RPC provider for production traffic.
- **The demo relayer uses a shared operator key** for most roles when
  pointed at testnet/mainnet, with one exception (`investigatorB`, via
  `INVESTIGATOR_B_PRIVATE_KEY`) needed to produce a genuinely distinct
  second investigator address — the contract's own `DuplicateReport`
  protection correctly rejects a second report from the same address on
  the same challenge, by design.
- **Predicate extraction is regex-based**, scoped to the claim shapes
  this MVP targets (funding/valuation/TVL/exploit claims); classification
  logic itself is deterministic either way.
